4 · Le routeur Dashboard() : 3 branches exclusives

@Composable
private fun Dashboard(params: DashboardParams, onLegacyAction: (LegacyAjustoDashboardAction) -> Unit) {
    with(params) {
        when {
            locationDisabled != null -> AjustoLocationDisabledView(
                title = locationDisabled.title,
                message = locationDisabled.message,
                buttonText = locationDisabled.buttonText,
                onButtonClick = { onLegacyAction(locationDisabled.buttonAction) }
            )
            networkAccessDisabled != null -> NoInternetView()
            else -> AjustoDashboardScreen(params = params, onClick = onLegacyAction)
        }
    }
}
Conséquence forte, souvent oubliée. locationDisabled et networkAccessDisabled ne sont pas des MessageBox : ce sont des écrans pleins qui remplacent tout le contenu. Si la localisation est désactivée, le message « batterie faible » n'est jamais affiché, même s'il existe dans le state. Il est calculé, transporté, stocké… et court-circuité au dernier moment.

Fabrique 1 — Badge

Stratégie : substitution totale. Le Core envoie title = nom du badge et message = badgeLevelText. Le Fragment les jette et met ses propres chaînes produit.

C'est ce qui produit « Félicitations pour votre nouvelle médaille! / Touchez pour la réclamer » de ta maquette de droite — ce texte n'existe pas dans le Core.

C'est la seule MessageBox cliquable du Dashboard, et la seule qui stocke un objet Badge à côté.

Fabrique 2 — Générique

Stratégie : pass-through. Titre, message et bouton viennent tels quels du Core, qui les a déjà localisés via LocalizedStringSource.

Seule l'icône est traduite, via getKoreIconKeyFromImageKey().

action n'est jamais renseigné ⇒ null ⇒ onBoxClick vaut null ⇒ la carte n'est pas cliquable. Elle couvre 6 des 7 types du Core.

Asymétrie clé. La fabrique 1 fabrique un contenu produit ; la fabrique 2 transporte un contenu Core. Deux philosophies opposées dans le même when. C'est pour ça qu'on ne peut pas remplacer l'une par l'autre mécaniquement.

Mapper 1 & 2 — dans le Fragment

private fun getKoreIconKeyFromImageKey(imageKey: ImageKey, colorKey: ColorKey?): AjustoDashboardIconKey? {
    val iconColor = getKoreIconColorFromColorKey(colorKey)      // ← mapper 2 imbriqué
    return when (imageKey) {
        CONTEXTUAL_MESSAGE_CLASSIFY           -> EditPen(iconColor)
        CONTEXTUAL_MESSAGE_BATTERY            -> BatteryLow(iconColor)
        CONTEXTUAL_MESSAGE_POLICY_EFFECTIVE   -> FileWithMedal(iconColor)
        CONTEXTUAL_MESSAGE_DEVICE_NOT_COMPATIBLE -> DeviceNotCompatible(iconColor)
        DEVICE_BRAND_NOT_COMPATIBLE           -> WarningSign(iconColor)
        else                                  -> null
    }
}

private fun getKoreIconColorFromColorKey(colorKey: ColorKey?): AjustoDashboardIconColor =
    when (colorKey as? AjustoContextualMessage.Color) {
        AjustoContextualMessage.Color.ACCENT  -> AjustoDashboardIconColor.BRAND
        AjustoContextualMessage.Color.WARNING -> AjustoDashboardIconColor.WARNING
        AjustoContextualMessage.Color.BLUE    -> AjustoDashboardIconColor.BLUE
        AjustoContextualMessage.Color.RED     -> AjustoDashboardIconColor.RED
        null                                  -> AjustoDashboardIconColor.DEFAULT
    }
Point d'architecture élégant. La couleur n'est pas un champ séparé de MessageBox : elle est portée par l'IconKey lui-même. sealed class AjustoDashboardIconKey(val color: AjustoDashboardIconColor?). Donc BatteryLow(RED) et BatteryLow(WARNING) sont deux valeurs distinctes du même type. C'est ce qui permet au Dashboard d'afficher correctement « batterie faible » en rouge et « économie d'énergie » en orange, alors que le Core envoie la même icône.

Le delay(500L) de la ligne 408. Ce n'est pas de la logique métier, c'est du timing d'animation : on laisse le fragment « badge réclamé » apparaître avant de faire disparaître la carte, sinon l'utilisateur voit un saut de layout derrière la transition. Un détail d'UX codé dans le Fragment — à ne pas oublier si un jour la logique bouge ailleurs.

Les 3 façons de faire disparaître une MessageBox

DéclencheurLigneEffet
Le Core envoie null (plus aucune condition vraie)—aucune des deux branches ne s'exécute — la carte reste affichée ⚠️

Bug latent du legacy. Le when (eventData) a une branche else -> {} vide. Quand le Core envoie null — c'est-à-dire quand plus aucune des 7 conditions n'est vraie, par exemple quand l'utilisateur rebranche son téléphone — le Fragment ne fait rien. L'ancienne carte reste à l'écran jusqu'au prochain message non-null ou jusqu'à un CloseMessageBox.

Observation. DashboardParams est une copie quasi identique de DashboardUiState, moins le champ badge. Pourquoi cette duplication ? Parce que DashboardUiState est une inner class du Fragment — donc un type Android — et que le Composable ne doit pas dépendre du Fragment. DashboardParams est la barrière. Elle est private et vit dans le fichier du Screen.

Le champ badge: Badge? ne franchit pas cette barrière : c'est un type Core Java, il reste côté Fragment. La MessageBox ne transporte que l'intention (action = ClaimBadge), et le Fragment retrouve le badge dans son propre state au moment du clic.

                // ← ce bloc ne s'exécute JAMAIS : onButtonClick est toujours null

10 · Les 6 subtilités à retenir

① Un seul slot MessageBox

DashboardParams.messageBox est un champ unique, pas une liste. Cohérent avec le Core, dont la cascade ne renvoie qu'un message à la fois. Il n'y a jamais deux cartes empilées.

② La couleur voyage dans l'IconKey

MessageBox n'a pas de champ couleur. C'est iconKey.color qui la porte. BatteryLow(RED) ≠ BatteryLow(WARNING). Élégant, et c'est ce qui fait fonctionner la distinction batterie / économie d'énergie côté Dashboard.

③ Le bouton est du code mort

onButtonClick n'est jamais passé par AjustoDashboardScreen. Le buttonText du Core (présent uniquement sur « marque non compatible ») n'est donc jamais affiché. Le paramètre existe, la branche existe, rien ne l'active.

④ Une seule carte cliquable sur sept

Seule la fabrique badge renseigne action. Les 6 autres types produisent action = null ⇒ onBoxClick = null ⇒ pas de clickable dans le modifier.

⑤ Deux écrans pleins peuvent l'éclipser

Localisation désactivée ou réseau absent ⇒ Dashboard() route vers un écran plein et le messageBox n'est jamais rendu, même s'il est présent dans le state.

⑥ null ne nettoie pas

Le when du listener a un else -> {} vide. Quand le Core envoie null, l'ancienne carte reste affichée. Seuls CloseMessageBox et le claim réussi la font disparaître.
