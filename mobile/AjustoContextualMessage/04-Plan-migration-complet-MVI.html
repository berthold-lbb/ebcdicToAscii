C · Plan d'amélioration du Shim

C.1 · Ce que le shim est censé être, et ce qu'il est devenu

La documentation dans le code est claire :

// AjustoSummaryShim.kt
interface AjustoSummaryShim {
    // Expose uniquement signaux runtime absents du repository summary.
    val state: StateFlow<AjustoSummaryShimState>
}

« Signaux runtime » = réseau, localisation, batterie. Mais l'état porte un quatrième champ :

data class AjustoSummaryShimState(
    val hasNetworkAccess: Boolean = true,       // signal runtime ✓
    val isLocationEnabled: Boolean = true,      // signal runtime ✓
    val isBatteryLow: Boolean = false,          // signal runtime ✓
    val contextualMessage: AjustoContextualMessagePayload? = null   // ← DONNÉE MÉTIER
)
Le shim mélange deux responsabilités. Le message contextuel n'est pas un signal runtime : c'est une donnée métier, calculée par une cascade de 7 règles, avec un cycle de vie, un cache, et un reset à la déconnexion. Il appartient à un repository, pas à un shim de signaux device.

Symptôme visible : c'est le shim qui pilote startObserving()/stopObserving() du bridger. Un objet censé exposer « la batterie est-elle faible » gère l'abonnement à TripService.

C.3 · Pourquoi le ShimImpl est coincé dans shared/ — et comment l'en sortir

Ce n'est pas un oubli de rangement. Regarde ses deux premiers imports :

import ca.dgag.ajusto.kore.info.DeviceInfo
import ca.dgag.ajusto.kore.info.NetworkState

Or modules/feature/ajusto/domain/build.gradle.kts ne déclare que :

implementation(projects.modules.transverse.domain)
implementation(libs.kotlin.stdlib)
implementation(libs.koin.core)
implementation(libs.kotlinx.datetime)
Le module feature ne peut pas voir les types Kore. Tant que le shim en dépend, il ne peut pas déménager. La solution n'est pas de le déplacer — c'est de couper la dépendance en interposant un port, exactement comme pour le message contextuel.
Avant — dépendance directe aux types Kore
class AjustoSummaryShimImpl(
  private val deviceInfo: DeviceInfo,     // Kore
  private val networkState: NetworkState, // Kore
  private val contextualMessageSource: …,
  dispatcher: CoroutineDispatcher = Dispatchers.Default
) : AjustoSummaryShim {

  private val shimScope =
    CoroutineScope(SupervisorJob() + dispatcher)

  override val state = combine(
    deviceInfo.isLocationEnabledStateFlow,
    networkState.connectionTypeStateFlow,   // ignoré (_)
    contextualMessageSource.contextualMessagesStateFlow
  ) { isLocationEnabled, _, contextualMessage ->
    AjustoSummaryShimState(
      hasNetworkAccess  = networkState.hasNetworkAccess(),
      isLocationEnabled = isLocationEnabled,
      isBatteryLow      = deviceInfo.isBatteryLow(),
      contextualMessage = contextualMessage
    )
  }.onStart      { …startObserving() }
   .onCompletion { …stopObserving()  }
   .stateIn(shimScope, WhileSubscribed(5_000), currentState())
}

package com.desjardins.assurancedommages.mobile.ajusto.domain.summary.model

/**
 * Message contextuel affiché sur le sommaire Ajusto.
 *
 * Les 7 premières variantes correspondent une à une aux règles de la cascade
 * `AjustoContextualMessageHelper.findContextualMessage()` du Core natif.
 * [GoodToKnow] provient d'une source éditoriale distincte.
 *
 * Un seul message est affiché à la fois — arbitrage dans le repository.
 */
sealed interface AjustoContextualMessage {
    val title: String
    val message: String

    /** Règle 1 — appareil de marque non prise en charge. Seul message actionnable du Core. */
    data class DeviceBrandNotCompatible(
        override val title: String,
        override val message: String,
        val buttonText: String?,
        val onButtonClick: (() -> Unit)?
    ) : AjustoContextualMessage

    /** Règle 2 — appareil non compatible. */
    data class DeviceNotCompatible(override val title: String, override val message: String) : AjustoContextualMessage

    /** Règle 3 — batterie faible ET non en charge. Tint Core : RED. */
    data class LowBattery(override val title: String, override val message: String) : AjustoContextualMessage

    /** Règle 4 — mode économie d'énergie actif ET pas d'enregistrement. Tint Core : WARNING. */
    data class PowerSaving(override val title: String, override val message: String) : AjustoContextualMessage

    /** Règle 5 — invitation à classifier des trajets. */
    data class ClassifyInvite(override val title: String, override val message: String) : AjustoContextualMessage

    /** Règle 6 — police pas encore en vigueur. */
    data class PolicyEffective(override val title: String, override val message: String) : AjustoContextualMessage

    /**
     * Règle 7 — badge réclamable.
     * ⚠️ [title] et [message] portent le NOM du badge et son niveau, pas le texte affiché.
     * La présentation substitue les chaînes produit — voir ContextualMessageMapper.
     */
    data class ClaimableBadge(
        override val title: String,
        override val message: String,
        val badgeIdentifier: String
    ) : AjustoContextualMessage

    /** Conseil éditorial — n'est PAS produit par le Core. Icône ampoule bleue. */
    data class GoodToKnow(
        override val title: String,
        override val message: String,
        val source: String? = null,        // ex. « selon la CAA »
        val externalId: String? = null     // traçabilité analytics
    ) : AjustoContextualMessage
}
Pourquoi onButtonClick: (() -> Unit)? dans un modèle domaine ? C'est discutable — une lambda dans un modèle est une entorse à la pureté. La justification : l'exécutable du Core est un WeakReference vers un listener que seul le Core sait résoudre ; le domaine ne peut pas le reconstruire. L'alternative (§B5) est de ne pas le porter et d'émettre une Action à la place — plus pur, mais il faut reproduire la modale côté KMP. Décision à prendre explicitement.

// AjustoContextualMessageBridger.kt — réécrit
class AjustoContextualMessageBridger(
    private val tripService: () -> TripService
) : AjustoContextualMessageDataSource {

    override fun observe(): Flow<AjustoContextualMessage?> = callbackFlow {
        val sm = SCRATCHSubscriptionManager()
        tripService().contextualMessageObservable
            .observeOn(queue = UiThreadDispatchQueue.newInstance())
            .subscribe(object : SCRATCHObservableCallback<CoreMessage?>(sm) {
                override fun onEvent(eventData: CoreMessage?) { trySend(eventData.toDomain()) }
            })
        awaitClose { sm.cancel() }
    }

    private fun CoreMessage?.toDomain(): AjustoContextualMessage? = when {
        this == null -> null
        this is BadgeContextualMessage -> ClaimableBadge(title(), message(), badge().identifier)
        this is ExecutableContextualMessage -> DeviceBrandNotCompatible(
            title(), message(), messageButton(), { buttonExecutable().execute() })
        messageIcon() == CONTEXTUAL_MESSAGE_DEVICE_NOT_COMPATIBLE -> DeviceNotCompatible(title(), message())
        messageIcon() == CONTEXTUAL_MESSAGE_BATTERY &&
            messageIconTint() == Color.RED -> LowBattery(title(), message())
        messageIcon() == CONTEXTUAL_MESSAGE_BATTERY -> PowerSaving(title(), message())
        messageIcon() == CONTEXTUAL_MESSAGE_CLASSIFY -> ClassifyInvite(title(), message())
        messageIcon() == CONTEXTUAL_MESSAGE_POLICY_EFFECTIVE -> PolicyEffective(title(), message())
        else -> null
    }
}

□ Batterie faible          → icône batterie ROUGE, pas orange

□ Appareil non compatible  → icône dédiée

□ Déconnexion/reconnexion  → aucun message du compte précédent
□ Changement de langue     → le message se retraduit sans rechargement

□ Dashboard legacy         → strictement identique à avant, sur les 7 types
